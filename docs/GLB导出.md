# 导出 GLB（带骨骼）

工具栏「导出 GLB」把当前模型写成一个自包含的 `.glb`：几何、材质贴图、关节层级、蒙皮权重
（`JOINTS_0/WEIGHTS_0`，超过 4 个影响再写 `JOINTS_1/WEIGHTS_1`）以及 `inverseBindMatrices`
一起打包，Blender / UE / three.js 打开就能直接摆姿势，不用先做一次绑定。

## 和「导出 OBJ」的区别

| | 导出 OBJ | 导出 GLB |
| --- | --- | --- |
| 几何 + 材质贴图 | 有 | 有 |
| 骨骼层级 | 无（OBJ 没有这个字段） | 有，节点名沿用游戏骨骼名 |
| 蒙皮权重 | 无 | 有，按 4 个一组拆 attribute |
| 姿势 | 冻结在当前几何 | 保持绑定姿势（bind pose），可继续摆 |
| 适合 | 只需要模型文件、要进别的工具重新拓扑 | 想保留骨骼、做动作、做动画对比 |

## 坐标系

和动画导出共用同一套换算：UE 的 X/Y/Z 反射到 glTF 的右手系，单位从厘米换到米
（`basis = [[0,.01,0,0],[0,0,.01,0],[-.01,0,0,0],[0,0,0,1]]`）。关节节点的局部 TRS 由
`gl_pose()` 逐根换算，`inverseBindMatrices` 用同一 basis 共轭，所以静止状态下蒙皮结果
严格等于顶点原位置（`tests/test_static_glb.py` 里有这个断言，误差 < 1e-6）。

## 没有骨骼的模型

纯静态网格（`SkeletalMesh` 以外、或没有权重表的）会提示「这个模型没有骨骼」，请改用
「导出 OBJ」；导出器本身也支持写不带 skin 的 GLB（`skinned=False`），只是界面按模型类型
做了引导。

## 资源占用

GLB 自带全部用到的贴图（PNG 原样嵌入），所以文件通常比 OBJ 小、比只导几何的 `.uemodel`
大。角色类资产一般在 1–10 MB 之间。
