# 改枪（Gunsmith）完整逻辑

> 面向对象：要接手这套装配逻辑、或者想查「某把枪为什么错位」的人。
> 代码根目录：`VertexViewer-source/`；主模块 `core/gunsmith.py`（约 2080 行）。
> 文档对应版本：2026-11-09（含 XM250 修正）。

---

## 1. 一句话总览

改枪页做的事只有一件：**把「游戏自己的装配数据」翻译成每个配件的 4×4 世界矩阵。**

```
游戏档案（DataTable）
   GunDescTable          预设树：谁挂在谁身上、插在哪个挂点
   GunPresetBoundsTable  官方拼好后的整体包围盒
   PartSocketsTable      挂点 ID → 挂点名
   WeaponPartsMeshSocketNameInfo  每个网格有哪些挂点、各在哪
   CommonItemAssets_Weapon        道具 ID → 1P/3P/UI 网格
        │
        ▼
core/sockets.py  解析挂点表，给出 socket_matrix(vpath, name) → 4×4（GL 米）
core/presets.py  解析预设树 + 包围盒
core/items.py    道具 ID → 网格路径（权威）
        │
        ▼
core/gunsmith.py
   preset_loadout()      抄预设：这件是哪个道具、挂谁、什么挂点
   official_loadout()    没有预设时按命名规则兜底
   resolve_placements()  算每个配件的世界矩阵（核心）
   assemble()            叠加伸展量 / 手调 → 烘焙成一个 Mesh 交给渲染
        │
        ▼
app/gunsmith_page.py  界面：选主件、官方配件、逐件调、存方案、导出
```

渲染层不参与任何「对齐」——它拿到网格和矩阵就画。所有位置问题都在 `resolve_placements()` 里解决。

## 2. 游戏档案：用到哪五张表

| 表（`Content/DataTables/...`） | 模块常量 | 内容 | 用途 |
| --- | --- | --- | --- |
| `WeaponPart/GunDescTable.uasset` | `presets.VP_DESC` | 每个 DesId 一行，行里是节点数组；节点 = `[Index, ParentIndex, ItemId, ParentSocketId]` | 官方预设：装哪几件、每件的父节点、插哪个挂点 |
| `WeaponPart/GunPresetBoundsTable.uasset` | `presets.VP_BOUNDS` | 每个 DesId 的 `Origin` / `Extent`（UE cm） | 标定「伸出量」——伸缩托拉出多少、枪管露多长 |
| `WeaponPart/PartSocketsTable.uasset` | `sockets.VP_PSOCK` | 挂点 ID → 挂点名 | 把预设里的 `ParentSocketId` 翻成 `Bar_point` 这种名字 |
| `WeaponPart/WeaponPartsMeshSocketNameInfo.uasset` | `sockets.VP_SOCK` | 每个网格的挂点名 + 位置 + 旋转 | 真正算矩阵的数据 |
| `CommonItemAsset/CommonItemAssets_Weapon.uasset` | `items.VP_ITEMS` | 5,470 行，道具 ID → `Item1PMeshPath` / `Item3PMeshPath` / `ItemUIMeshPath` / `ItemDroppedMeshPath` | 道具 ID 换网格的**权威答案** |

解析结果缓存（第一次解析几十秒，之后秒开）：

| 缓存 | 路径 |
| --- | --- |
| 挂点 | `%LOCALAPPDATA%\VertexViewer\weapon_sockets.json` |
| 预设 + 包围盒 | `%LOCALAPPDATA%\VertexViewer\weapon_presets.json` |
| 道具 → 网格 | `%LOCALAPPDATA%\VertexViewer\item_meshes.json` |
| 改枪方案 | `%LOCALAPPDATA%\VertexViewer\gunsmith\*.json` |
| 伸展量标定 | `VertexViewer-source/core/part_offsets.json`（随包发布） |

坐标换算统一在 `sockets.ue_matrix()`：UE 厘米 + FRotator(每轴角度) → GL 米，
位置 `GL = (y, z, -x) * 0.01`，旋转 `P_MAP @ fr_matrix(rot) @ P_MAP.T`。
**记住这个映射**：后面所有「枪尾短 8cm」之类的判断都是在这个坐标系里量的。

## 3. 道具 ID → 网格：三条路，顺序不能反

`preset_loadout()` 里逐节点取网格（`gunsmith.py:1616`）：

1. `items.resolve(node_item)` —— 查 `CommonItemAssets_Weapon`。
   **这是唯一权威的**：连没有挂点、因此不在挂点表里的枪托、小握把都能查到。
2. `sockets.item_meshes(node_item)` —— 挂点表顺带记的「道具→网格」，通常只有大件；
   取 `_3P` 优先、名字最短的那个，再走 `presets.vpath_of()` 换成带 `../../../DeltaForce/` 前缀的路径。
3. `guess_part_vpath(base_vpath, family)` —— 按「枪名片段 + 槽位前缀」猜（最后兜底）。

历史教训：只有 1、2 两步时，XM250 的枪托（道具 `13040000110`）不在挂点表里，
被猜成 `Sto_A_XM250STD_090`（其实是另一个道具 `13040000174`），整枪短 8.76cm；
同一预设里的战术灯 `13160000005` 更是直接被丢掉。加了第 1 步以后两件都对了。

### 4.2 族表 `FAMILY_OF_PREFIX`（`gunsmith.py:73`）

资产名第一段 → 挂接族：

```
Rec→receiver  Bar→barrel  Han→handguard  Muz→muzzle  Mag→mag  Sto→stock
PisG→grip  FroG→foregrip  Acl/Sco→optic  Bip→bipod  Att/Dev→tactical
```

`mount_family(vpath, slot)`（`gunsmith.py:116`）：先看前缀；前缀不认识才退回槽位；都不认识给 `other`。

### 4.3 各族挂在谁身上：`PARENT_FAMILY`（`gunsmith.py:102`）

```
muzzle    → barrel
foregrip  → handguard, barrel
bipod     → barrel, handguard
tactical  → handguard, barrel
```

其余族（barrel/handguard/stock/grip/mag/optic）默认挂在**机匣**上。

## 5. 一个配件：`PartSpec`（`gunsmith.py:248`）

| 字段 | 含义 |
| --- | --- |
| `vpath` | 网格资产路径（`../../../DeltaForce/...`） |
| `slot` | 槽位 key |
| `name` | 显示名 |
| `offset` | 用户手调的额外位移（米，叠加在挂点之上） |
| `rot` | 用户手调的旋转（度，yaw/pitch/roll） |
| `scale` | 缩放倍率 |
| `socket` | 挂在父件的哪个挂点；空 = 自动挑（挑中后会写回，界面可见） |
| `auto_scale` | 旧版自动缩放系数，仅兼容 |
| `anchored` | 点过「自动对齐」才会按锚点摆 |
| `slot_fit` | 官方装配标记 |
| `skin_source` | 换肤前的原部件，换肤失败时用它回退 |
| `parent_item` | **预设里这件挂在哪个道具上**（父节点道具 ID）——防「同名挂点挂错父件」 |
| `parent_socket_id` | 预设里的挂点 ID，只用于排查 |

`Recipe`（`gunsmith.py:310`）= `base` + `base_name` + `parts[]` + `skin_id` + `skin_base`，
存到 `%LOCALAPPDATA%\VertexViewer\gunsmith\<名字>.json`。

## 6. 装配核心：`resolve_placements()`（`gunsmith.py:1064`）

输入：主件 vpath + 主件 LOD + `[(PartSpec, MeshLOD)]`。
输出：`{id(spec): 4×4 世界矩阵}`（GL 米）。

### 6.1 轮次模型

不是一次遍历，而是**最多 `max(3, 件数+1)` 轮**的定点迭代：

- 每轮遍历 `pending`；
- 需要「先等父件摆好」的件放进 `rest`，下一轮再来；
- 某一轮没有任何进展（`len(rest) == len(pending)`）就停，剩下的走包围盒兜底。

为什么要轮次：枪口要挂在枪管上、前握把要挂在护木上，而父件本身也可能是第二轮的产物；
更麻烦的是**同名挂点**（`Common_point` 在机匣和护木上都有）要等两边都摆好才能判定该贴谁。

### 6.2 分支一：预设写死了父件（`gunsmith.py:1120`）

`spec.parent_item` 能在本轮装配里找到对应 `PartSpec`（靠 `sockets.item_of_mesh()` 反查道具 ID）：

1. 父件还没摆好 → 进 `rest` 等下一轮；
2. 父件摆好了 → 父矩阵就是父件的世界矩阵；
3. 先试**精确同名**挂点 `named_socket(parent_vpath, spec.socket)`；
4. 不行再按族的候选表 `find_socket(..., prefer=spec.socket)`；
5. 命中：`mat = parent_mat @ socket_local`。

这是「导轨附件挂到另一根导轨」问题的正解——游戏预设早就写清楚了，不用猜。

### 6.3 分支二：没写父件，按族推（`gunsmith.py:1138`）

1. `PARENT_FAMILY` 里该族有父族（枪口→枪管、前握把→护木…）：
   在**已摆放**的件里找第一个该族的件当父件；找不到且有同族件还没摆好 → 等下一轮；
2. 取父件：默认机匣（`base_vpath` + 单位矩阵）；
3. 若 `spec.socket` 非空，进「**拥有者试装**」：
   - 收集所有拥有这个挂点名的候选父件：机匣 + 所有已摆放的配件；
   - 逐个试算 `owner_mat @ socket_local`，量「配件包围盒 ↔ 父件包围盒」的间隙；
   - 取间隙最小者，且必须 `<= 2cm` 才采纳（否则说明挂错了人）；
   - 若还有拥有者没摆好，先 `rest` 等一轮再判断；
   - 都不满足：退化成「同名挂点唯一定位」或 `_place_by_socket()`；
4. 没有 `spec.socket`：直接 `_place_by_socket()`（按族候选表在父件上找第一个存在的挂点）。

### 6.4 摆完之后的两条路（`gunsmith.py:1199`）

| 情况 | 处理 | 是否允许后续「贴缝」 |
| --- | --- | --- |
| `mat is None`（找不到挂点） | `_bbox_fallback()` → `_snap_mount_face()` → `_snap_optic_to_rail()` | 允许 |
| `mat` 有值（走挂点） | 记入 `socket_placed`；瞄具再过一道 `_seat_on_surface()` | **禁止** |

为什么禁止：挂点给的是游戏里的插入点，再按包围盒「贴一下」只会把它从挂点上拽下来。
XM250 的瞄具被压进机匣 5.6cm、弹匣被推偏 4cm，都是早期在这里多做了一步造成的。

### 6.5 收尾三连（`gunsmith.py:1221`）

```
plan = _fit_to_official(...)       # 沿枪长补伸出量（要预设对得上才动）
plan = _push_barrel_out(...)       # 枪管整根藏在机匣里 → 推到露出 2cm
plan = _close_mount_gaps(..., keep=socket_placed)   # 给没挂点的件贴缝
```

## 7. 六个几何修正函数（阈值全在这里）

### 7.1 `_bbox_fallback()`（`gunsmith.py:619`）——没有挂点时的老办法

按主件包围盒把件摆到「大致该在的位置」：长轴 `ax = argmax(size)`，竖直轴 `up`：

| 族 | 规则 |
| --- | --- |
| barrel / muzzle / handguard | 后端贴主件前端（`t[ax] = base_hi - part_lo`） |
| stock | 前端贴主件后端（`t[ax] = base_lo - part_hi`） |
| mag / grip / foregrip | 上沿贴主件下沿，长轴按 `8%`（弹匣）或 `2%`（握把）偏移 |
| optic | 底面贴主件顶面，长轴前移 `6%` |
| 其它 | 长轴居中 |

### 7.2 `_snap_mount_face()`（`gunsmith.py:719`）——按族的「贴合面」

`_MOUNT_FACE`（`gunsmith.py:706`）规定每族该贴哪一面：

| 族 | 轴 | 方向 |
| --- | --- | --- |
| stock | x | -1（前端贴机匣后端） |
| barrel / muzzle / handguard | x | +1（后端贴父件前端） |
| grip / mag / foregrip / bipod / tactical | y | -1（上沿贴父件下沿） |

护栏：
- 另外两轴必须与父件相差 `<= 6cm`，否则不许贴（防止把旁边的件拽过来）；
- 需要的位移 `<= 1mm` 或 `> 30cm` 就不动。

**只对没有挂点的件生效。**

### 7.3 `_snap_optic_to_rail()`（`gunsmith.py:752`）——瞄具吸导轨

用父件包围盒顶面当导轨面：间隙 `|gap| <= 1.5cm` 不动；瞄具在父件长轴范围外不动。
**只对没有挂点的瞄具生效。**

### 7.4 `_seat_on_surface()` + `_surface_top_at()`（`gunsmith.py:657` / `680`）——走挂点的瞄具

问题：`Sco_point` 只给插入点。XM250 的 `Sco_point` 在 `y=-0.004`（枪身中线），
而导轨顶面在 `y=0.173`，照挂点摆就是「瞄具陷进机匣」。

做法：
1. 在父件顶点里取 `|x-瞄准中心| <= 4cm` 且 `|z-瞄准中心| <= 3cm` 的点（不足 8 个就把 x 窗口翻倍）；
2. 取这些点的最高 y 当「该位置的导轨面高度」；
3. 瞄具底面比它低 `0.2cm ~ 40cm` 才抬，其它情况不动。

只对 `optic` 生效，且只抬不压。

### 7.5 `_fit_to_official()`（`gunsmith.py:812`）——用官方包围盒补「伸出量」

挂点不含伸缩托拉出量、两脚架张开角、消音器拧入深度，这些只能从
`GunPresetBoundsTable` 反推。

流程：
1. 算当前拼装的总包围盒；
2. 在这把枪的所有 DesId 里挑「标定基准」：先要求**装的是同一批道具**
   （`_preset_matches()` ≥ `0.70`），在此前提下取包围盒误差最小的；
3. 误差 `<= 1cm` 直接不动（挂点精度就这样）；
4. **只沿枪长一个轴**（`long_axis = argmax(包围盒尺寸)`）补；
5. 每个边：找出「顶在这个边上的那一件」（必须唯一，且族属于
   `_FIT_FAMILIES = {stock, barrel, muzzle, handguard, bipod}`），只平移它；
6. 护栏：如果这一挪会让它离最近件的间隙变大（从父件上拽开），就不挪。

为什么要限定族、又限定轴：竖直/横向的差多半是瞄具高矮、弹鼓宽度，硬拽会把贴好的件扯下来；
XM250 的瞄具就是被「全轴对齐」压进机匣的。

### 7.6 `_push_barrel_out()`（`gunsmith.py:999`）——枪管推出

只在「枪管长度 ≥ 25cm 且**整根**落在机匣包围盒内」时触发：
沿枪长把它推到「机匣前端 + 2cm」，挂在它上面的枪口（按 `parent_item` 找子孙）一起平移。
正常枪（枪管本来就在外面）不会触发。

XM250：`Bar_point` 在机匣中部，枪管 `0.012..0.367` 全被机匣 `..0.647` 包住，改完 `x+` 误差从 `-7.44cm` 收到 `-0.63cm`。

### 7.7 `_close_mount_gaps()`（`gunsmith.py:935`）——没挂点的件贴缝

- 只处理 `_CLOSE_FAMILIES` 且**不在 `keep`（`socket_placed`）里**的件；
- 找最近邻（含机匣盒）；
- 间隙 `<= 0.5cm` 或 `> 8cm` 不动；
- 必须**只差一个轴向**（`sep` 非零分量恰好 1 个），按正负方向推平；
- 斜着差一截的判不清方向，放手。

## 8. 烘焙：`assemble()`（`gunsmith.py:1230`）

```
base_lod（机匣） + 每个配件（按 PartSpec 顺序）
  → resolve_placements() 得到每个件的世界矩阵
  → 逐件叠加：
        world = plan[id]
        world = world @ trs(part_offset(vpath))   # 伸缩托默认伸展量（core/part_offsets.json）
        world = world @ trs(spec.offset)          # 用户手调位移
        world = world @ trs(spec.rot)             # 用户手调旋转
        moved = _apply_matrix(lod, world, spec.scale)
  → merge(items)  把多段网格合成一个 MeshLOD + 材质表
  → ModelBundle(mesh="gunsmith", materials, textures)
```

注意叠加顺序：**先挂点、再伸展量、再手调**。手调永远是在游戏坐标之上加，不会破坏挂点关系
（除非用户手动把它拖走）。

`merge()`（`gunsmith.py:510`）会把每个件的材质统一重编号，输出一张合并材质表；
`_section_ranges()`（`gunsmith.py:492`）记录「哪一段属于哪个件」，界面点选配件时靠它高亮。

## 9. 官方配件从哪来：`preset_loadout()` / `official_loadout()`

### 9.1 `preset_loadout(base_vpath)`（`gunsmith.py:1582`）——抄预设

1. `sockets.item_of_mesh(base_vpath)` 拿主件道具 ID；
2. `presets.presets_of_item(item)` 拿所有包含它的 DesId（XM250 有 43 套）；
3. 逐套解析 `nodes_of(desid)`，每个非根节点：
   - `ParentSocketId` → 挂点名（`socket_id_name`）；
   - 道具 ID → 网格（§3 的三步）；
   - **跨族纠错**：若「预设挂点族」与「网格实际族」都是大件却不一致
     （例：ScarH 的枪托道具指向 `Other_minimi-1913adapter`），换成同族同枪的候选；
     小件（握把底座、弹匣底板）不纠错，否则会多出第二只握把；
   - 记录 `parent_item`（父节点道具 ID）与 `parent_socket_id`；
   - 同 `(slot, socket)` 去重；
4. 多套之间打分：`(大件齐全且件数≥4 得 2 分, 件数, -跨族错误数)`，取最高；
5. `_dedupe_major()` 同族大件只留第一件。

`_dedupe_major()`（`gunsmith.py:1686`）：`{stock, barrel, handguard, muzzle, grip, foregrip, bipod}`
同族只留第一件。**弹匣、瞄具不在此列**——加长弹匣 + 底板、主镜 + 红点都是正常搭配。

### 9.2 `official_loadout(base_vpath)`（`gunsmith.py:1705`）——没有预设时兜底

1. 先试 `preset_loadout()`，拿到 ≥2 件就用它；
2. 否则按命名规则：
   - `gun_code()` 取型号码（`M4A1-Std_001`），`_gun_tokens()` 拆片段；
   - 遍历全部 `_3p.uasset`，片段命中即候选，前缀决定槽位；
   - `score = Σ(10 + 片段长度)`，型号码完全命中 +30，同目录 +6，同皮肤 +4；
   - 每槽位取分最高 1 件，顺序 `barrel → handguard → muzzle → optic → grip → mag → stock`；
3. 还不够 2 件：退回「同皮肤目录整套件」。

`missing_parts()`（`gunsmith.py:1393`）统计「预设有、包里没网格」的槽位，界面上提示
「包内缺网格：…」。

## 10. 换皮肤链路（`core/weapon_skins.py`）

皮肤不是「换贴图」，而是**换一整套模型**（每套皮肤自带全套模具，机匣号都不同）。

关键函数：

| 函数 | 作用 |
| --- | --- |
| `part_identity(path)`（:32） | 取部件身份（`Rec_AR_M4A1-Std_001`），忽略 1P/3P/皮肤后缀 |
| `_gun_key(text)`（:134） | 从部件名推枪名键（`rec_ar_m4a1-std_001` → `m4a1`），去族词、类别词 |
| `_kit_gun_index()`（:153） | 皮肤套装目录 → 枪名键 |
| `_kit_receiver(kit)`（:166） | 套装里的 `rec_` 3P 机匣 |
| `_skin_choices(family, gun_key)`（:228） | 「同部件号」+「同枪整套皮肤」（`cross=True`）两个来源 |
| `_kit_part_for(source, skin)`（:266） | 严格部件号对不上时，按槽位 + 同名片段在套装里找对应件 |
| `apply_skin(recipe, skin)`（:322） | 换主件 + 逐件映射，返回 `SkinApplication`（含 `retained` 保留件） |
| `official_parts(recipe)`（:451） | 换肤后按官方装配重配（`同步官方皮肤配件` 勾选时走这条） |

界面 `_apply_skin()`（`app/gunsmith_page.py:425`）：
1. `ws.apply_skin()` 得到新方案；
2. 勾了「同步官方皮肤配件」再过 `ws.official_parts()`；
3. 逐件试加载，失败则用 `skin_source` 对应的原部件回退（`_previous_skin_part()` 按部件身份 + 挂点匹配）；
4. `_rebuild()`；
5. 状态栏：`已应用皮肤：X · 当前 N 个配件 · M 个配件无对应皮肤，保留原选件`。

## 12. 兜底与降级矩阵

| 缺什么 | 后果 | 代码兜底 |
| --- | --- | --- |
| 没装游戏 / 表读不到 | 没有预设、没有挂点 | `preset_loadout()` 返回空 → `official_loadout()` 按名字猜；`resolve_placements()` 全走 `_bbox_fallback()` |
| 道具不在 `CommonItemAssets_Weapon` | 该件可能猜错/丢失 | 退 `item_meshes()` → 再退 `guess_part_vpath()`；仍没有就记进 `missing_parts()` |
| 网格没有挂点 | 位置只能估 | `_bbox_fallback()` + `_snap_mount_face()` + `_snap_optic_to_rail()` + `_close_mount_gaps()` |
| 同名挂点多个拥有者 | 可能挂错父件 | 「拥有者试装」取间隙最小且 ≤2cm；不确定就等下一轮 |
| 预设和我们装的件对不上（overlap<0.7） | 官方包围盒不可当标尺 | `_fit_to_official()` 直接返回原计划 |
| 枪管整根在机匣内 | 看不出枪管 | `_push_barrel_out()` |
| 缺皮肤对应件 | 该件消失 | `skin_source` 回退原部件，状态栏计数 |
| 某件网格解析失败 | 该件消失 | 页面跳过并提示「暂不可加载，已保留可用选件」 |

## 14. 已知边界（不是 bug，别乱改）

1. **弹鼓宽度**：XM250 的 75 发弹鼓本身就比机匣宽，官方包围盒两侧各差 4.9cm 属正常。
2. **瞄具叠高**：主镜 + 红点叠在一起会让顶面比官方包围盒高 4.6cm。
3. **伸缩托伸展量**：`part_offsets.json` 只标了少数需要额外后移的托；
   没标的按「贴住机匣」处理——视觉上更稳，但不等于游戏里拉出的长度。
4. **`GunsmithPartFixTransform` 没用上**：全表只有 1 条记录（233 字节，fix 全 0），
   不是通用修正表，别拿它当标定源。
5. **JSON 契约键**：导出/方案里的 `"dfmap"` 等键是导出器输出契约，不要为了改名去动。
6. **挂点与包围盒冲突时以挂点为准**：这是 XM250 那一轮的结论，别再改回去。
